================================================================================
  USB-протокол управления Romeo (прошивка ROMEO_USB_PROTO)
  Интерфейс: виртуальный COM-порт (USB CDC), как в Arduino Leonardo
================================================================================

ПАРАМЕТРЫ ПОРТА
  Скорость (для настройки терминала): 115200
  Формат: 8 бит данных, без чётности, 1 стоп-бит (8N1)
  Окончание строки: символ LF (0x0A), в коде '\n'
  Символ CR (0x0D), '\r', игнорируется

ФОРМАТ КОМАНД (хост → плата)
  Одна команда = одна текстовая строка в кодировке ASCII.
  Первая лексема — имя команды, далее через один пробел — аргумент (если нужен).
  Регистр букв в имени команды не важен (ping = PING).

--------------------------------------------------------------------------------
КОМАНДЫ (отправлять с переводом строки \n в конце)
--------------------------------------------------------------------------------

PING
  Проверка связи.
  Пример байтов (ASCII):  P I N G \n
  Ответ: одна строка  PONG 1

?  (или HELP, H)
  Справка: несколько строк с перечнем команд, в конце строка OK.

MF
  Оба мотора вперёд с фиксированной «крейсерской» скоростью (cfg::kMotorCruiseSpeed в config.h, по умолчанию 220).
  Ответ: OK

MB
  Оба мотора назад с той же скоростью по модулю.
  Ответ: OK

MS
  Оба мотора в 0 (то же действие, что у STOP).
  Ответ: OK

TL  /  TR
  Разворот на месте: одна гусеница вперёд, другая назад
  (скорость = cfg::kMotorTurnSpeed, по умолчанию 200).
  TL — влево, TR — вправо.
  Если в config.h kMotor1IsLeft=false, направление инвертируется.
  Ответ: OK

TANK <left> <right>
  Танковая раскладка: задаются скорости левой и правой гусениц
  целыми числами -255..255 каждая. Это позволяет ехать вперёд/назад
  и одновременно подкручивать (l != r) — как стик на джойстике.
  Примеры:
    TANK  200  200\n  — прямо вперёд
    TANK -200 -200\n  — прямо назад
    TANK  200 -200\n  — разворот вправо на месте
    TANK   80  200\n  — плавный поворот налево с движением вперёд
  Ответ: OK
  Ошибки: ERR ARG (нет двух чисел), ERR TANK_VAL

M1 <скорость>
  Двигатель 1 (встроенный драйвер). Скорость: целое от -255 до 255.
  Знак: направление, модуль: ШИМ (чем больше по модулю, тем быстрее).
  Примеры:
    M1 0\n      — останов
    M1 200\n    — вперёд (условно)
    M1 -200\n   — назад
  Ответ при успехе: OK
  Ошибки: ERR ARG (нет числа), ERR M1_VAL (не распознано число)

M2 <скорость>
  То же для двигателя 2.
  Ошибки: ERR ARG, ERR M2_VAL

S1 <угол>
  Сервопривод 1 (PAN, пин 9). Низкоуровневая команда без лимитов: 0…180 (целое).
  Пример: S1 90\n
  Ответ: OK
  Ошибки: ERR ARG, ERR S1_VAL

S2 <угол>
  Сервопривод 2 (TILT, пин 10). Низкоуровневая команда без лимитов: 0…180.
  Ошибки: ERR ARG, ERR S2_VAL

--- БАШНЯ (с программными лимитами из config.h) ---

PAN <угол>
  Поворот башни (servo 1, пин 9). Угол ограничен [kPanMinDeg..kPanMaxDeg].
  По умолчанию диапазон 0..180.
  Пример: PAN 120\n
  Ответ: OK
  Ошибки: ERR ARG, ERR PAN_VAL

TILT <угол>
  Наклон вверх/вниз (servo 2, пин 10). Угол ограничен [kTiltMinDeg..kTiltMaxDeg].
  По умолчанию 30..150 (для защиты механики).
  Пример: TILT 80\n
  Ответ: OK
  Ошибки: ERR ARG, ERR TILT_VAL

TURRET <pan> <tilt>
  Установить оба угла одной командой (с теми же лимитами).
  Пример: TURRET 90 90\n
  Ответ: OK
  Ошибки: ERR ARG, ERR TURRET_VAL

PANL [step]    PANR [step]
  Шаг поворота башни влево / вправо. step — необязательный
  положительный шаг в градусах (по умолчанию kTurretStepDeg = 5).
  Пример:
    PANL\n      — на 5° влево
    PANR 15\n   — на 15° вправо
  Ответ: OK
  Ошибка: ERR STEP_VAL (если шаг ≤ 0 или нечисло)

TILTU [step]   TILTD [step]
  Шаг наклона вверх / вниз (с теми же правилами, что у PANL/PANR).

--- ПЛАВНЫЙ (СКОРОСТНОЙ) РЕЖИМ БАШНИ ---
Идея: одной командой задаётся угловая скорость, плата сама плавно крутит
сервопривод до новой команды или до 0. Это устраняет «рваное» движение,
когда удалённое устройство шлёт частые мелкие шаги.

Внимание: серво-выход использует writeMicroseconds() (под-градусная точность),
поэтому даже при медленных скоростях движение должно быть плавным,
а не «лесенкой» по 1°.

--- КОРОТКИЕ КОМАНДЫ (УДОБНО ДЛЯ КЛИЕНТА) ---
Используют скорость cfg::kTurretDefaultRateDegPerSec (по умолчанию 90 °/с),
если аргумент не задан. Опциональный аргумент — положительное число град/с.

PL [v]   — начать плавный поворот башни ВЛЕВО
PR [v]   — начать плавный поворот ВПРАВО
TU [v]   — начать наклон ВВЕРХ
TD [v]   — начать наклон ВНИЗ
TS       — стоп плавного хода башни (синоним TSTOP)

Сценарий «зажал кнопку → плавно поехала, отпустил → стоп»:
  нажал «вправо»:    PR
  отпустил «вправо»: TS
  (или PL для влево, TU/TD для вверх/вниз)

ВАЖНО:
  Любая позиционная команда (PAN, TILT, TURRET, S1, S2, HOME, STOP)
  автоматически останавливает плавный ход (внутренне сбрасывает скорость в 0).

Внутри плата считает положение в милли-градусах с шагом ~10 мс цикла
и применяет лимиты как у PAN/TILT. По достижении лимита скорость
автоматически обнуляется.

PANV <скорость>
  Угловая скорость поворота башни, град/с (целое со знаком).
  Положительное — увеличение угла PAN, отрицательное — уменьшение.
  0 — остановиться (удерживая текущий угол).
  Ограничивается ±cfg::kTurretMaxRateDegPerSec (по умолчанию 240).
  Пример:
    PANV 90\n   — крутить вправо со скоростью 90°/с
    PANV -60\n  — крутить влево
    PANV 0\n    — стоп
  Ответ: OK
  Ошибки: ERR ARG, ERR PANV_VAL

TILTV <скорость>
  То же для наклона.
  Ошибки: ERR ARG, ERR TILTV_VAL

TURRETV <pan_v> <tilt_v>
  Установить обе скорости одной командой.
  Пример: TURRETV 60 -40\n
  Ошибки: ERR ARG, ERR TURRETV_VAL

TSTOP
  Остановить плавный ход башни (PANV=0, TILTV=0). Текущий угол сохраняется.
  Команда STOP делает то же самое + STOP моторов.

Сценарий «зажал кнопку → плавно поехала, отпустил → стоп»:
  нажал «вправо»:    PANV 90
  отпустил «вправо»: PANV 0

HOME
  Установить башню в «домашнее» положение (kPanHomeDeg, kTiltHomeDeg).
  Гасит скорость PANV/TILTV.
  Пример: HOME\n
  Ответ: OK

POS
  Запросить текущее положение башни.
  Ответ одной строкой: POS PAN <deg> TILT <deg>
  Пример ответа: POS PAN 90 TILT 90

--- АНАЛОГОВЫЙ ВХОД (АЦП, 10 бит, опорное напряжение AVCC ≈ 5В) ---

A0 .. A5
  Прочитать аналоговый вход и вернуть его значение.
  Доступно cfg::kAdcChannels каналов (по умолчанию A0..A5 — это «свободные»
  пины на Romeo V2.2, не занятые моторами/серво/ИК).
  Ответ одной строкой:
      A<n> <raw> <millivolts>
    где raw  ∈ 0..1023, millivolts = raw * cfg::kAdcReferenceMv / 1023.
  Пример:
    запрос:  A0\n
    ответ :  A0 512 2502         (около 2.5В на входе)
  Ошибка: ERR ADC_CH (если канал вне допустимого диапазона)

A <n>
  То же, но номер канала аргументом.
  Пример:  A 3\n   →  A3 1023 5000

VBAT
  Прочитать батарею шуруповёрта через делитель на A1.
  Настройки в config.h:
    kBatteryAdcChannel = 1       (A1)
    kBatteryDividerR1Ohm = 47000 (BAT+ → A1)
    kBatteryDividerR2Ohm = 10000 (A1 → GND)
    kBatteryCalibrationPpm = 1010000

  Ответ:
      VBAT <battery_mV> <raw> <pin_mV>

  Где:
    battery_mV — пересчитанное напряжение батареи до делителя;
    raw        — сырое значение АЦП 0..1023;
    pin_mV     — напряжение непосредственно на A1.

  Пример:
    запрос: VBAT\n
    ответ : VBAT 19220 669 3372

  Для ваших измерений 18.3→19.22, 18.0→18.88 и т.д. выставлены:
    kAdcReferenceMv = 5170
    kBatteryCalibrationPpm = 1010000

ПРИМЕЧАНИЯ
  • Опорное напряжение по умолчанию задано в config.h (kAdcReferenceMv = 5000).
    Реальное AVCC при питании от USB обычно НЕ равно ровно 5.000В
    (часто 4.6..5.1В из‑за просадки, кабеля, USB‑порта). Поэтому
    «миллиВольты» в ответе могут отличаться от мультиметра.
    Для точных измерений калибруйте — см. ниже команды VCC и VREF.
  • Если нужно опрашивать несколько входов подряд — просто шлите команды
    одну за другой; каждая команда отвечает одной строкой.
  • Если на входе бывает > 5В — ставьте делитель напряжения, иначе
    повредите МК.

--- КАЛИБРОВКА АЦП ---

VCC
  Измерить фактическое напряжение питания МК (AVCC) через внутренний
  bandgap 1.1В и сразу принять его как опорное (reference) для будущих
  чтений A0..A5.
  Ответ:  VCC <millivolts>
  Пример: VCC\n  →  VCC 4870
  Замечание: точность bandgap ~10%, поэтому это «грубая авто‑калибровка».
  Для лучшей точности — см. VREF <mv> ниже.

VREF
  Показать текущее опорное напряжение, использующееся для пересчёта
  raw → мВ.  Ответ:  VREF <millivolts>

VREF <mv>
  Задать опорное напряжение вручную в милливольтах. Допустимый диапазон
  500..7000. Используется при следующих чтениях A0..A5.
  Точная процедура:
    1) Подайте на A0 известное напряжение (или измерьте AVCC мультиметром
       между 5V и GND на плате).
    2) Если меряли AVCC: команда  VREF <измеренное_mv>   (например 4980).
    3) Перепроверьте  A0  — мВ в ответе должны совпадать с мультиметром.
  Ответ:  VREF <millivolts>   (после применения)
  Ошибка: ERR VREF_VAL — значение вне диапазона / нечисло.

VREF AUTO
  То же, что VCC.

--- OLED SSD1306 128x64 (I2C: SDA=D2, SCL=D3, адрес 0x3C) ---

  Экран UCTRONICS 0.96" (или аналог SSD1306) подключается к шине I2C Romeo:
    VCC → 5V (или 3.3V), GND → GND, SDA → D2, SCL → D3.

  В прошивке хранится кольцевой массив из cfg::kMsgCount строк (по умолчанию 8),
  каждая до cfg::kMsgTextLen символов (≈21 символ на строке экрана).
  На экране видны последние 8 строк; при переполнении старые затираются.

MSG <текст>
  Добавить строку в массив сообщений и обновить экран.
  Весь текст после первого пробела — одна строка (пробелы внутри допустимы).
  Пример: MSG Привет Pi\n
  Ответ: OK
  Ошибка: ERR ARG — нет текста.

MSGCLR
  Очистить массив сообщений и экран.
  Пример: MSGCLR\n
  Ответ: OK

MSGL
  Вывести текущий массив сообщений в USB (для отладки с ПК).
  Формат ответа:
      MSGL <count>
      MSG <index> <text>
      ...
      OK
  Пример:
    MSGL 2
    MSG 0 Romeo ready
    MSG 1 test
    OK

  Примечание: ИК-приёмник перенесён на D12, т.к. D3 занят I2C SCL.

--- БОРТОВОЙ СВЕТОДИОД (LED_BUILTIN, на Romeo это пин 13) ---

LON
  Включить светодиод. Ответ: OK.

LOFF
  Выключить светодиод. Ответ: OK.

LTG  (или LTOGGLE)
  Переключить состояние светодиода. Ответ: OK.

LED ON | OFF | TOGGLE | 1 | 0 | T
  Развёрнутый вариант той же команды.
  Пример: LED ON\n   LED 0\n   LED T\n
  Ответ: OK
  Ошибка: ERR LED_VAL — неизвестный аргумент.

LED   (без аргумента)
  Запросить текущее состояние.
  Ответ одной строкой:  LED ON  или  LED OFF

FIRE
  Короткий импульс ИК-передатчика (несущая ~38 кГц, длительность задаётся в прошивке).
  Пример: FIRE\n
  Ответ: OK

IR
  Синоним FIRE (та же функция).
  Пример: IR\n

STOP
  Оба мотора в 0 (M1 и M2). Эквивалентно команде MS.
  Пример: STOP\n
  Ответ: OK

--------------------------------------------------------------------------------
ОТВЕТЫ И СОБЫТИЯ (плата → хост)
--------------------------------------------------------------------------------

OK
  Команда принята и выполнена без ошибки (где применимо).

ERR <код>
  Ошибка разбора или выполнения. Коды:
    ARG       — не хватает аргумента (например, послали M1 без числа)
    M1_VAL    — неверное значение для M1
    M2_VAL    — неверное значение для M2
    TANK_VAL  — неверные значения для TANK (нужны два числа)
    S1_VAL    — неверное значение для S1
    S2_VAL    — неверное значение для S2
    PAN_VAL   — неверное значение для PAN
    TILT_VAL  — неверное значение для TILT
    TURRET_VAL — неверные значения для TURRET (нужны два числа)
    PANV_VAL  — неверное значение для PANV
    TILTV_VAL — неверное значение для TILTV
    TURRETV_VAL — неверные значения для TURRETV
    RATE_VAL  — неверная скорость для PL/PR/TU/TD (≤0 или нечисло)
    LED_VAL   — неизвестный аргумент для LED
    ADC_CH    — неверный номер канала АЦП
    VREF_VAL  — неверное значение для VREF (вне 500..7000)
    STEP_VAL  — неверный шаг для PANL/PANR/TILTU/TILTD (≤0 или нечисло)
    LINE_OVF  — строка команды длиннее буфера (обрезание/сброс)
    UNKNOWN   — неизвестная команда

PONG 1
  Ответ на PING.

BOOT ROMEO_USB_PROTO 1
  Однократно при старте/сбросе микроконтроллера (после подключения USB может
  появиться не сразу — дождитесь порта).

EVT HIT <seq> <t_ms>
  Зарегистрировано «попадание» по ИК-приёмнику (D12, опрос в главном цикле).
    seq   — порядковый номер события (uint16)
    t_ms  — значение millis() на момент события (после антидребезга)
  Пример: EVT HIT 3 12458
  Может прийти несколько строк подряд, если событий было несколько.

ПРОВЕРКА С ПК (РЕКОМЕНДУЕТСЯ: Python + pyserial)
--------------------------------------------------------------------------------
  На части систем Windows класс System.IO.Ports.SerialPort нестабилен с USB CDC
  (Leonardo): команды уходят, ответа нет. Надёжный вариант — pyserial:

    pip install pyserial
    python tools/serial_ping_test.py COM14

  (подставьте свой COM из диспетчера устройств)

--------------------------------------------------------------------------------
ПРИМЕРЫ ДЛЯ RASPBERRY PI (Python 3, пакет pyserial)
--------------------------------------------------------------------------------

  import serial
  ser = serial.Serial("/dev/ttyACM0", 115200, timeout=0.1)
  ser.write(b"PING\n")
  print(ser.readline().decode().strip())   # ожидается PONG 1

  ser.write(b"M1 100\n")
  print(ser.readline().decode().strip())   # OK

  ser.write(b"S1 45\n")
  print(ser.readline().decode().strip())

  ser.write(b"STOP\n")
  ser.write(b"FIRE\n")

  # чтение входящих строк (BOOT, EVT HIT, ответы на команды):
  while ser.in_waiting:
      line = ser.readline().decode(errors="ignore").strip()
      if line:
          print(line)

ПРИМЕР ДЛЯ WINDOWS (PowerShell, один порт COM5 — замените на свой)

  $p = new-Object System.IO.Ports.SerialPort COM5,115200,None,8,one
